Delta Schéma

Compare deux exports SQL et écrit le script qui met l'ancienne base au niveau de la nouvelle.

Base ANCIENNE

— la cible, celle en production

Base NOUVELLE

— la source, celle de dev
Colle-le dans phpMyAdmin → onglet SQL de la base ancienne. Fais une sauvegarde avant. 

      


      


      

        

          
1. Sortir les deux exports

          
Ancienne base (Hostinger) : hPanel → Bases de données → phpMyAdmin → choisis la base → onglet Exporter → méthode Personnalisée → dans « Données », coche Structure seule → Exécuter.

          
Nouvelle base (XAMPP) : http://localhost/phpmyadmin, même chemin. En ligne de commande : mysqldump -u root --no-data --skip-add-drop-table ma_base > new.sql

          
Structure seule = fichier léger et diff propre. Les INSERT sont de toute façon ignorés par l'outil.


          
2. Versions : ce qu'il faut savoir

          
MariaDB 7.4 n'existe pas — le 7.4 d'Hostinger, c'est la version de PHP. Leurs serveurs MySQL tournent sous MariaDB 10.x. L'outil lit la vraie version dans l'en-tête du dump (-- Server version: …) et l'affiche sous chaque panneau. Si l'en-tête manque, force la cible dans le menu déroulant.

          
Le sens de la migration compte : générer depuis MariaDB 10.4 (XAMPP) vers du 10.5/10.6 ne pose aucun souci. L'inverse — descendre vers plus ancien, ou vers MySQL 5.7 — peut casser sur DEFAULT (expression), les contraintes CHECK, le type JSON ou les collations utf8mb4_0900_*. Ces cas sont réécrits automatiquement et listés dans les avertissements.


          
3. Lire le résultat

          
    
            
  • Différences — table par table : colonnes ajoutées, modifiées, supprimées, index, clés étrangères, options.
    • 
            
  • Script SQL — les CREATE et ALTER dans l'ordre sûr : tables d'abord, colonnes, index, puis clés étrangères.
    • 
            
  • Avertissements — perte de données possible, NOT NULL sans valeur par défaut, index trop longs en utf8mb4, incompatibilités de version.
    •

  1. Sauvegarde complète de l'ancienne base (export avec les données).

  2. Teste le script sur une copie, pas directement en production.

  3. Les suppressions sont désactivées par défaut : elles n'apparaissent qu'en commentaire, sauf si tu coches « Inclure les suppressions ».
    4. 
            
  4. Une colonne NOT NULL ajoutée sans DEFAULT échoue si la table contient déjà des lignes — l'outil te le signale.

5. Limites connues

          
    
            
  • Les renommages de colonnes sont vus comme « supprimée + ajoutée ». L'outil propose un CHANGE en commentaire quand le type correspond.
    • 
            
  • Le partitionnement, les tables système et les CREATE TABLE … SELECT ne sont pas analysés (signalés).
    • 
            
  • Tout se passe dans ton navigateur : aucun dump n'est envoyé nulle part.
